01

Overview

SVN that behaves like the built-in Git

A rewritten fork of an extension abandoned in 2017, with the missing commands added and, since 0.4.0, the working copy actually read.

The Explorer marks every file the way the built-in Git integration does, driven by svn status. There is a Source Control panel and quick diff marks in the editor gutter, and it works even when the folder you opened is a subdirectory of the working-copy root, which is where most of these extensions give up.

The dialogs are all there too, in a right-click submenu with keybindings and multi-root workspace support: commit, update, log, diff, blame, revert, add and the rest, each running against what you clicked.

It needs TortoiseSVN itself, and the decorations additionally need svn.exe, which TortoiseSVN installs only if you tick the command-line tools in its installer. If either is missing the extension says so in its output channel rather than failing silently.

Status in the Explorer

Every file marked from svn status, the way the built-in Git integration used to do it.

Source Control panel

Changes listed where you expect them, not in a separate window.

Quick diff in the gutter

Modified lines marked in the editor as you type.

Subdirectory working copies

Works when the opened folder sits below the working-copy root.

The full dialog set

Commit, update, log, diff, blame, revert and add, with keybindings and multi-root support.

Says what is missing

If TortoiseSVN or the command-line client is absent, the output channel tells you which.

Open source under MIT. A rewritten fork of TangYanxin/vscode-tortoise-svn, abandoned since 2017.
